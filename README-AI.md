# Bad Apple on ESP32

Plays the Bad Apple video on an ESP32 board with a TFT screen. The whole video is stored in the
flash memory of the firmware, so no SD card or network is needed.

## How it works

1. **Encoder** (`encoder/main.py`, Python): reads the video, makes each frame black and white, and
   stores each run of same-coloured pixels as a run length. Run lengths use a variable-length code
   (VLQ). The output is `src/vid.h`.
2. **Firmware** (`src/main.cpp`, C++): decodes one frame at a time and draws it with
   `drawFastHLine`.
3. **Flash**: `src/vid.h` is compiled into the firmware and marked `PROGMEM`, so it stays in flash.

Current data: every frame of the video (6569 frames). The partition table is `huge_app.csv`
(3 MB app partition).

## Repository layout

| Path | Contents |
|---|---|
| `platformio.ini` | Board, framework, libraries and partition table |
| `src/main.cpp` | Firmware: decoder and display loop |
| `src/vid.h` | Encoded video (generated by the encoder) |
| `encoder/main.py` | Encoder |
| `encoder/search_vlq.py` | Search for the best VLQ widths |
| `encoder/vlq_search_skip*.json` | Search results |
| `include/`, `lib/`, `test/` | PlatformIO folders (empty apart from a README) |

The source video (`encoder/Touhou - Bad AppleCR.mp4`) is not in the repository because of its size.

## Build and upload

```
pio run                 # compile
pio run -t upload       # compile and flash
pio device monitor      # serial output, 115200 baud
```

## Regenerate `src/vid.h`

```
pip install opencv-python numpy
python encoder/main.py --skip 1 --vlq 5,2,1,3,2,1,1,3,2,1
```

- `--skip N`: keep every N-th source frame (1 = every frame).
- `--vlq a,b,...`: segment widths of the run-length code. The widths and the maximum run length are
  written into `src/vid.h`, and the firmware reads them from there.

To search for better widths:

```
python encoder/search_vlq.py --skip 1
```

The result is written to `encoder/vlq_search_skip1.json`.

## Known limits

- **Playback speed:** the firmware waits `FRAME_DELAY_MS` (30 ms) after each frame, plus the drawing
  time. Stored frames play at the device's speed, not at the source's 30 fps. Time-based playback
  (skipping frames when behind) is not implemented.
- **Display configuration:** TFT_eSPI's display type and pins are not in the repository. The build
  uses the library defaults.
- **Updates:** `huge_app.csv` has one app slot, so over-the-air updates are not possible. USB
  flashing works.
